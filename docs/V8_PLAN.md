# v8 計画

v7（Gemini / Antigravity 版）から新エンジン v8 への作り直しの方針と順番です。
v7 の固定点: タグ `gemini-v7.0`（40a85cc）と `gemini-final`（8fa2575）。v7 の出力は `data/archive/gemini_v7_20261126/` に保存済み。

## 方針

- **正解**はユーザーの耳の評価（[docs/evaluations/](evaluations/README.md)）と Studio One での手直し履歴。**基準**は同じオケに乗った本家の声。プロのカバー音源は上限・下限の参考にとどめる。自 MIX は正解にも上限にも使わない（2026-11-26 凌「二つともそんなに納得してない、これを天井にはしないで」）。
- **目標はその曲のオケに対する相対値**で決める。公式オフボがある曲は「原曲 − オフボ」で声全体を、ない曲はカラオケ分離でリードとバッキングを分けて求める。
- **処理は 4 層**:
  1. 曲を通して固定のチェーン。実機 VST3 を CMA-ES で最適化し、目的関数は ST-ITO 的なもの、DiffVox の分布を事前分布に使う。
  2. フレーズ単位の部分ラウドネスに基づく音量ライド。区間ごとの EQ・サチュレーション切替は廃止し、Studio One のクリップゲイン／オートメーションとして書き出す。
  3. 音節単位で子音・アタックを双方向に（潰れていれば持ち上げ、強すぎれば抑える）整える。
  4. 空間はオケ自身の残響から決め、ディレイは Beat This! の拍格子に合わせる。
- **根拠のない定数を書かない。** 値には出典（ユーザー評価・計測・論文・既存プロファイル）を残す。

## Phase 3 の結果（子音を潰す／強くする処理段、2026-11-27、レビュー前）

方法: `mix-auto mix --export-debug-stems` が `debug_stems/stages/` に各段の出力を書き出す（`src/mix_automation/debug_taps.py`。既定の音とマスターは不変で、Phase 2 のレンダーとのヌルは 3 曲とも master −64〜−65 dB、VocalBus −60〜−62 dB、LUFS 差 0.00）。`scripts/analysis/stage_attribution.py` で、子音を RX 掃除後のリードで一度だけ検出し、各段を直前の段と比べる（C Δ子音／母音、Q 帯域減衰・ゲインの谷・重心）。全表は `docs/evaluations/stage_attribution.md`。

- 3 曲共通の系統: Pro-Q の静的 EQ が歯擦音を母音比 +2.3〜+2.6 dB 持ち上げ、コンプ（VCA・LA-2A）がさらに +1〜2 dB 持ち上げる。一方で RX ディエッサー・Pro-Q の動的高域帯域・Soothe2 が子音の中でゲインの谷（各 −1〜−2 dB）を作る。「持ち上げてから動的に削る」構成で、子音は総量では大きいまま削られた痕跡が残る。
- カバー比較（同じ分離モデル、絶対値）: lad-1 の「さ」は v7 の方が大きく明るい（比 −3.5 dB・重心 8.6 kHz、カバー Ado −8.1 dB・7.5 kHz、Tongari −5.0 dB・6.8 kHz。他 4 本は検出なし）。「潰れ」は量の不足ではなく、動的な削りの質感である可能性（推測）。six-9 は v7 で歯擦音が検出されず、フレーズの 4–12k/0.2–4k も v7 が最も暗い（−14.6 dB、カバー −10.4〜−13.2）。量では再現しない。「じゅ／ず」は有声で歯擦音検出に乗らないため、有声摩擦の扱いは Phase 4 で見直す（推測）。
- バス・2mix の段は、オケが歯擦音帯域を埋めるため Q が大きく出る（lad-1 の谷 −8.2 dB）が、処理の痕跡ではない（参考値扱い）。
- Phase 2 の訂正: fil-1 のアドリブはハモリ stem ではなくリード（main）側にある（ハモリ stem は 2:30〜2:41 無音）。
- 未確定: six-7 の対象は Phase 2 と同じ 2:26.2 の子音で、指摘の 2:29 から 3 s ずれている（窓 ±3 s 内でいちばん強い子音）。歌詞単位の対応ができる Phase 4 で確かめ直す。

v8 のチェーン設計への示唆（各 1 行、推測を含む）:
- 歯擦音の制御は 1 段にまとめ、EQ・コンプの後に置く。RX ディエッサー・Pro-Q 動的高域・Soothe2 を重ねない（谷が合計 −5 dB になる）。
- 静的 EQ の高域持ち上げは、後段の動的な削りと相殺させない量に抑える。
- コンプの段数を減らし、アタックは子音を通しすぎない設定（無音直後の立ち上がりで +4〜7 dB）にする。または子音の後にゆっくり戻る処理を置く。
- 下処理（ステージ 1）では子音の量を変えない（ゲインライダーが対象の子音で子音比を +0.6〜+1.5 dB 動かしている）。

後の段階に回したもの:
- 展開ごとの空間の自動化（A〜B メロでプレートを切る、サビ前だけホール）→ R6。
- ハモリ・コーラス・ダブル → R6。
- スラップディレイ（150〜190 ms）との選択、1176 系パラレル、ボーカルバス EQ → R4 以降で候補として検討。
- 音量の追従は、ダッキング前のオケとセンド前のリードで測っている。そのため最終の声−オケは目標より約 0.8 LU 大きくなる（エバ）。R4 で測る位置を揃える。
- ディレイの音価: 1/16 が 100 ms 未満になるときは 1/8 に倍にする（`chain.delay_note_s`）。シックスは Beat This! がオフボーカルで 187.5 BPM（マスターでは 93.8）と倍テンポに出るため、1/8 = 160 ms になる。テンポの倍・半分の曖昧さは R4 以降で扱う。

### R3 の確認（2 曲、v7 はハモリ・コーラスを除いた版）

v7 側は Phase 2 のレンダーの debug_stems（lead_dry＋wet＝声、inst_unmasked＝オケ）を、v7 自身の 2mix 関数に通して作った（`scripts/analysis/v8r3_compare.py`）。声−オケはペア音源パイロットと同じ定義（VocalBus と処理後オケの積分 LUFS 差）。

| 曲 | 版 | 声−オケ LU | 声の S/M dB | マスター LUFS |
|---|---|---|---|---|
| エバ | v7 メインのみ | +0.75 | −18.0 | −12.1 |
| | v8 | −1.70 | −18.1 | −9.6 |
| シックス | v7 メインのみ | −0.37 | −17.7 | −9.5 |
| | v8 | −2.35 | −18.0 | −9.5 |

- v8 の声−オケは、2 曲ともプロの範囲（−5.5〜+0.2 LU）の中に入った。v7 のエバは上に外れている。
- 声の S/M はほとんど変わらない（ダブラーの Mid −6 dB、プレートの幅を足しても約 −18 dB）。エバの「浮いていた」（Side/Mid が狭い）は、ボーカルバス単体ではなくマスターで測った値なので、この表とは別物。R4 で参照と比べる。
